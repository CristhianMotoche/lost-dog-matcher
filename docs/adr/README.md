# Architecture decision records

Architecture decision records (ADRs) capture significant choices that affect the project's structure, dependencies, operation, or long-term maintenance. They explain the context, the chosen approach, and its consequences.

Create an ADR when a decision has meaningful alternatives or lasting tradeoffs. Do not create one for routine implementation details. Number records sequentially, keep accepted records immutable, and add a new ADR when superseding an earlier decision.

Each ADR uses this lightweight structure:

```text
# Title

Status: Proposed | Accepted | Superseded
Date: YYYY-MM-DD

## Context

## Decision

## Consequences
```
